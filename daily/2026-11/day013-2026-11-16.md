## 📖 核心概念

### 1. 可复现是什么，为什么难

美国国家科学院 2019 年的报告把两个常被混用的词分开：**可复现（reproducibility）** 指用同样的数据和代码得到一致的结果；**可重复验证（replicability）** 指另一项研究用新收集的数据回答同一个问题，得到一致的结论（[NASEM 2019](https://doi.org/10.17226/25303)）。今天讲的是前者。它是最低要求：连作者自己都重跑不出来的结果，更谈不上被别人验证。期刊也在收紧要求，例如 PLOS Biology 规定，2026 年 1 月 1 日起投稿的论文必须公开复现结果所需的全部代码，确有法律或伦理限制的需要说明理由（[政策原文](https://journals.plos.org/plosbiology/s/code-availability)）。

计算结果“跑不出来”，常见原因有五类：

| 原因 | 生信中的例子 |
|---|---|
| 手工步骤 | 在 Excel 里删掉几个“异常”样本，没有任何记录 |
| 环境变化 | pandas 3 改变了链式赋值的行为（Day 010），同一段代码换个版本，结果就不同 |
| 数据变化 | AlphaFold DB 升级到 v6、RefSeq 记录升了版本号，重新下载得到的已经不是同一份数据 |
| 随机性 | 训练 / 测试集划分、权重初始化、数据打乱都要用随机数，不固定种子，每次结果都不同 |
| 路径与顺序 | 写死的绝对路径（`C:\Users\me\...`）；依赖集合或目录的遍历顺序 |

### 2. 《Good enough practices》：每个人都做得到的规范

Wilson 等人 2017 年的这篇文章写给刚开始写代码的研究者，只收录每个人都能做到的做法，文末的 Box 1 汇总了全部建议。与今天最相关的有四组：

- **数据**：保存原始数据并在多处备份；用脚本记录每一步处理；每条记录要有唯一 ID。原始数据只读，永远不手工修改。
- **软件**：每个程序开头写一段说明；把程序拆成函数；消除重复代码；明确写出依赖；用参数切换程序的行为，而不是注释掉一段代码；附一个小的示例数据集。
- **项目组织**：每个项目一个目录；文档放 `doc/`，原始数据放 `data/`，清理和分析产生的文件放 `results/`，源代码放 `src/`；文件名要反映内容。
- **记录变更**：小步修改、经常同步、使用版本控制（Day 004）。

按这些建议，一个小项目可以这样组织（在论文示例的基础上加了环境文件和 `notebooks/`）：

```text
tumor-classifier/
├── README.md          # 项目是什么、怎么安装、一条复现命令
├── LICENSE            # 许可证
├── CITATION.cff       # 别人如何引用（GitHub 能识别的格式，可选）
├── environment.yml    # 环境描述（Day 003）
├── data/
│   ├── raw/           # 原始数据：只读
│   └── processed/     # 由代码生成，随时可以删掉重建
├── src/               # 函数和主流程脚本
├── notebooks/         # 探索性分析
├── results/           # 图和表：全部由代码生成
└── doc/               # 笔记、文稿
```

一个实用的检验标准：**删掉 `results/` 和 `data/processed/` 之后，能不能用一条命令把它们原样重建出来？**

### 3. 锁定环境：记下当时用的是哪个版本

Day 003 已经学过用 `environment.yml` 描述环境。复现时还要区分两类文件：

| 文件 | 写什么 | 回答的问题 |
|---|---|---|
| 依赖声明：`environment.yml`、`requirements.txt`、`pyproject.toml` | 直接用到的包，可以只写版本范围 | 运行这个项目需要什么？ |
| 锁文件（lock file）：`pip freeze` 的输出，或 conda-lock、uv、pip-tools 生成的文件 | 所有包（包括间接依赖）的精确版本 | 当时用的到底是什么？ |

还有三点要注意：每个 Notebook 开头打印关键包的版本，结果文件旁边保存一份环境记录（练习 2 会自动生成）；Colab 的预装环境会不定期升级，今天能跑通的 Notebook，几个月后可能报错或者结果改变，对结果影响大的包要用 `pip install 包名==版本号` 固定；需要连操作系统和系统库一起固定时，用 Docker、Apptainer 等容器。

### 4. 控制随机性

- **NumPy**：用 `rng = np.random.default_rng(seed)` 创建生成器，把 `rng` 作为参数传给需要随机数的函数（Day 009）。不要依赖全局的 `np.random.seed()`：中途任何一行代码（包括你调用的库）多取了一个随机数，后面的结果就全变了。另外，NumPy 只保证旧的 `RandomState` 在不同版本间输出相同的随机数序列，新的 `Generator` 允许在版本升级时改变序列，这也是要记录版本号的原因之一。
- **Python 标准库**：用 `random.seed(seed)`。字符串的哈希值每次启动 Python 都会随机化，所以**集合（set）的遍历顺序可能每次都不一样**；需要固定顺序时，先用 `sorted()` 排序。
- **scikit-learn**：给有随机性的函数传入 `random_state=整数`。
- **PyTorch**（第 8 周开始用）：`torch.manual_seed(seed)` 会同时设置 CPU 和 GPU 的种子，但 GPU 上的部分运算本身就不确定，要逐位一致还需要 `torch.use_deterministic_algorithms(True)` 等设置，代价是运行变慢；换了 GPU 型号或 CUDA 版本，结果也可能不再逐位相同。

**种子不是超参数**。固定种子是为了让结果能够重现，而不是为了挑出“效果最好”的那个。样本量小的生物数据尤其敏感：在练习 1 中，只换随机种子，测试准确率就在 0.72 到 0.94 之间波动。报告模型性能时，应该用多个种子或交叉验证，给出均值 ± 标准差。

### 5. 局限

可复现不等于正确：有 bug 的流程也能被完美地重现。它也不保证结论在新数据上成立，那是可重复验证和泛化（generalizability）要回答的问题，第 25 周讲科研严谨性时还会展开。追求逐位相同有时代价很高，实践中更常见的目标是：多次运行的结论一致，差异在可以解释的范围内。

**练习 1 · 随机性从哪里来**

```python
import os
import subprocess
import sys

import numpy as np

# ---------- 1. 全局随机状态：中途多用了一个随机数，后面的结果全变 ----------
np.random.seed(0); a = np.random.normal(size=3)
np.random.seed(0); np.random.permutation(10); b = np.random.normal(size=3)  # 中途先打乱了一次样本顺序
print("global seed, same results?   ", np.allclose(a, b))

# 推荐：每个随机过程用自己的 Generator，作为参数传进函数
def add_noise(x, rng):
    return x + rng.normal(size=x.shape)

rng_split, rng_noise = np.random.default_rng(1), np.random.default_rng(0)
c = add_noise(np.zeros(3), rng_noise)
rng_split.permutation(10)                      # 打乱样本用的是另一个 rng，不影响噪声
d = add_noise(np.zeros(3), np.random.default_rng(0))
print("own Generators, same results?", np.allclose(c, d))

# ---------- 2. 隐藏的随机性：集合的遍历顺序 ----------
code = 'print(list({"TP53", "BRCA1", "EGFR", "MYC", "KRAS"}))'
for seed in ["1", "2", "3"]:
    env = {**os.environ, "PYTHONHASHSEED": seed}   # 每个新进程的字符串哈希种子
    out = subprocess.run([sys.executable, "-c", code], env=env, capture_output=True, text=True)
    print(f"PYTHONHASHSEED={seed}:", out.stdout.strip())
print("sorted:          ", sorted({"TP53", "BRCA1", "EGFR", "MYC", "KRAS"}))

# ---------- 3. 种子不是超参数：只换种子，准确率就在变 ----------
def make_data(rng, n=60, p=200, k=20, shift=0.8):
    """模拟表达数据：30 个正常、30 个肿瘤样本，只有前 20 个基因有差异。"""
    y = np.repeat([0, 1], n // 2)
    X = rng.normal(size=(n, p))
    X[y == 1, :k] += shift
    return X, y

def nearest_centroid_accuracy(X, y, seed, test_frac=0.3):
    rng = np.random.default_rng(seed)
    idx = rng.permutation(len(y))
    n_test = int(len(y) * test_frac)
    test, train = idx[:n_test], idx[n_test:]
    mu, sd = X[train].mean(0), X[train].std(0)          # 标准化参数只用训练集计算，避免数据泄漏
    Z = (X - mu) / sd
    centroids = np.stack([Z[train][y[train] == c].mean(0) for c in (0, 1)])
    dist = ((Z[test][:, None, :] - centroids[None]) ** 2).sum(-1)
    return (dist.argmin(1) == y[test]).mean()

X, y = make_data(np.random.default_rng(2026))
accs = np.array([nearest_centroid_accuracy(X, y, s) for s in range(10)])
print("accuracy by seed:", accs.round(3))
print(f"min {accs.min():.3f} | max {accs.max():.3f} | mean ± sd {accs.mean():.3f} ± {accs.std(ddof=1):.3f}")
```

期望输出（集合的三种顺序因 Python 版本而异，这里是 Python 3.13 的结果；要点是三行顺序各不相同）：

```text

own Generators, same results? True
PYTHONHASHSEED=1: ['EGFR', 'KRAS', 'MYC', 'TP53', 'BRCA1']
PYTHONHASHSEED=2: ['MYC', 'EGFR', 'KRAS', 'TP53', 'BRCA1']
PYTHONHASHSEED=3: ['BRCA1', 'TP53', 'KRAS', 'EGFR', 'MYC']
sorted:           ['BRCA1', 'EGFR', 'KRAS', 'MYC', 'TP53']
```

不设置 `PYTHONHASHSEED` 时，每次启动 Python 都会随机选一个哈希种子，所以“把基因集合转成列表再写进文件”这样的代码，每次运行的顺序都可能不同。第 3 部分里，数据和模型完全不变，只换了划分训练集和测试集的种子：测试集只有 18 个样本，错分一个就差 0.056。如果只报告种子 0 的 0.944，就高估了模型。

再用 Colab 的 `%%writefile` 把下面的流程脚本存成文件（这个魔法命令必须是单元格的第一行）：

```python
%%writefile mini-repro/src/pipeline.py
"""迷你可复现流程：原始数据 → 划分 → 标准化 → 最近质心分类 → 结果表与环境记录。

用法：python src/pipeline.py --seed 0
"""
import argparse
import hashlib
import json
import platform
from importlib.metadata import version
from pathlib import Path

import numpy as np
import pandas as pd

ROOT = Path(__file__).resolve().parents[1]           # 项目根目录：用相对位置，不写死绝对路径
RAW = ROOT / "data" / "raw" / "expression.csv"
RESULTS = ROOT / "results"


def make_raw_data(path, seed=2026, n=60, p=200, k=20, shift=0.8):
    """模拟“原始数据”，只在文件不存在时生成一次；此后把它当作只读文件。"""
    rng = np.random.default_rng(seed)
    label = np.repeat(["normal", "tumor"], n // 2)
    X = rng.normal(size=(n, p))
    X[label == "tumor", :k] += shift
    df = pd.DataFrame(X, columns=[f"gene{i:03d}" for i in range(p)])
    df.insert(0, "label", label)
    df.insert(0, "sample", [f"S{i:02d}" for i in range(n)])
    df.to_csv(path, index=False, float_format="%.6f")


def split(n, seed, test_frac=0.3):
    """随机划分训练集和测试集；随机性只来自传入的 seed。"""
    idx = np.random.default_rng(seed).permutation(n)
    n_test = int(n * test_frac)
    return np.sort(idx[n_test:]), np.sort(idx[:n_test])


def fit_predict(X_train, y_train, X_test):
    """最近质心分类：标准化参数只用训练集估计。"""
    mu, sd = X_train.mean(0), X_train.std(0)
    Z_train, Z_test = (X_train - mu) / sd, (X_test - mu) / sd
    classes = np.unique(y_train)                     # 排好序的类别，顺序固定
    centroids = np.stack([Z_train[y_train == c].mean(0) for c in classes])
    dist = ((Z_test[:, None, :] - centroids[None]) ** 2).sum(-1)
    return classes[dist.argmin(1)]


def main(seed):
    if not RAW.exists():
        make_raw_data(RAW)
    df = pd.read_csv(RAW)
    X, y = df.filter(like="gene").to_numpy(), df["label"].to_numpy()
    train, test = split(len(df), seed)
    pred = fit_predict(X[train], y[train], X[test])

    RESULTS.mkdir(exist_ok=True)
    out = RESULTS / f"predictions_seed{seed}.csv"
    pd.DataFrame({"sample": df["sample"].to_numpy()[test], "true": y[test], "pred": pred}).to_csv(out, index=False)
    env = {"seed": seed, "python": platform.python_version(), "platform": platform.platform(),
           **{pkg: version(pkg) for pkg in ["numpy", "pandas"]}}
    (RESULTS / f"environment_seed{seed}.json").write_text(json.dumps(env, indent=2))
    digest = hashlib.sha256(out.read_bytes()).hexdigest()[:12]
    print(f"seed={seed}  accuracy={np.mean(pred == y[test]):.3f}  sha256={digest}")


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description="mini reproducible pipeline")
    parser.add_argument("--seed", type=int, default=0, help="random seed for the train/test split")
    main(parser.parse_args().seed)
```

2. 为什么推荐用 `np.random.default_rng(seed)` 并把生成器作为参数传递，而不是在脚本开头调用一次 `np.random.seed(seed)`？

<details>
<summary>参考答案</summary>

1. 可复现指用同样的数据和代码得到一致的结果；可重复验证指另一项研究用新收集的数据回答同一个问题，得到一致的结论。如果连原作者的数据和代码都跑不出同样的结果，就无法判断后续研究的差异来自生物学本身，还是来自计算过程，更谈不上验证结论。
2. 全局种子是所有代码共享的一个状态：中途任何地方（包括调用的库）多取或少取一个随机数，后面所有随机数都会改变，而且很难察觉。为每个随机过程创建独立的生成器并显式传入，各部分互不干扰，也一眼就能看出哪里用到了随机性。
3. 很可能是代码遍历了一个字符串集合（set）或依赖了其他无序结构。Python 每次启动都会随机化字符串的哈希值，集合的遍历顺序因此可能变化，而这与 NumPy 种子无关。解决办法是在输出前用 `sorted()` 排序；调试时也可以设置环境变量 `PYTHONHASHSEED`，但它必须在 Python 启动前设置。
4. 原始数据和元数据放 `data/`（本笔记中细分为 `data/raw/`），清理和分析产生的文件放 `results/`（中间数据也可以单独放 `data/processed/`），源代码放 `src/`，文档放 `doc/`。原始数据只读，是因为它是唯一无法再生成的东西：一旦被手工改动，就无法知道改了什么，所有下游结果都失去了依据。所有修改都应该写成代码，作用在原始数据的副本上。
5. 模型性能会随数据划分和初始化而波动，样本量越小波动越大（练习 1 中准确率在 0.72 到 0.94 之间）。只报告一个种子的结果，读者无法判断这个数字是常态还是运气；如果还是挑出来的最好结果，就会系统性地高估性能。多个种子或交叉验证给出的均值 ± 标准差，同时反映了平均水平和稳定性。

</details>
