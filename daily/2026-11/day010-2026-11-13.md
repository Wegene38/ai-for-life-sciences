## 📖 核心概念

### 1. DataFrame 的结构

DataFrame 是一张带**行索引**（index）和**列名**的二维表，每一列有自己的数据类型；单独一列就是 Series。和 NumPy 最大的区别是 **pandas 按标签对齐**：两个表做运算时，先按行名、列名配对，再计算。例如 `counts / counts.sum(axis=0)` 会把每一列除以“同名样本”的总计数，不需要像 Day 009 那样操心维度。但这也意味着标签对不上时会产生缺失值（NaN），而不是报错。

### 2. 宽表与长表

- **宽表**：一行一个基因，一列一个样本，也就是常见的表达矩阵。适合矩阵运算，比如归一化、PCA。
- **长表**（也叫整洁数据，tidy data）：每行一个观测，例如“基因、样本、表达值”。再合并上样本信息，就能按条件、批次随意分组，也方便用 seaborn 画图（Day 011）。
- 两者用 `melt`（宽 → 长）和 `pivot` / `unstack`（长 → 宽）互相转换。

### 3. 选择数据

| 写法 | 含义 | 注意 |
|---|---|---|
| `df.loc[行标签, 列标签]` | 按标签选择 | 标签切片**包含终点**，如 `df.loc["G0001":"G0003"]` |
| `df.iloc[行位置, 列位置]` | 按位置选择 | 和 Python 切片一样，不包含终点 |
| `df[df["log2fc"] > 1]` | 布尔筛选 | 多个条件用 `&`、`\|`，每个条件要加括号 |
| `df.query("log2fc > 1 and biotype == 'lncRNA'")` | 用字符串写条件 | 条件复杂时更易读 |

### 4. 分组聚合：拆分、应用、合并

`groupby` 的思路分三步：按某列**拆分**成若干组，对每组**应用**一个函数，再把结果**合并**起来。例如 `long.groupby(["gene_id", "condition"])["logcpm"].mean()` 求出每个基因在每个条件下的平均表达。`agg` 可以同时算多个统计量；`transform` 返回和原表一样长的结果，适合做组内标准化，比如每个批次内部做中心化。

### 5. 合并表格

`merge` 相当于数据库的连接（join）：

- `how="inner"` 只保留两边都有的键；`how="left"` 保留左表所有行，右表缺的填 NaN；`how="outer"` 全部保留。
- **一定要检查合并结果**：`validate="one_to_one"` 能在键重复时立即报错，避免行数悄悄翻倍；`indicator=True` 会告诉你每行来自左表、右表还是两边都有。基因 ID 的版本号（如 `ENSG… .12`）、大小写不一致，都是合并时最常见的坑。

### 6. pandas 3.0 的变化（2026 年 1 月发布）

网上很多教程（包括今天的 PDSH，写于 2016 年）用的是旧版本，有两点要特别注意：

- **写时复制（Copy-on-Write）成为唯一模式**：任何筛选、切片得到的结果都表现得像一份副本。所以“链式赋值” `df[df["x"] > 0]["y"] = 1` **永远不会修改** `df`，pandas 会发出 `ChainedAssignmentError` 警告。正确写法是一次 `.loc` 完成：`df.loc[df["x"] > 0, "y"] = 1`。过去常见的 `SettingWithCopyWarning` 也随之取消了。
- **专门的字符串类型**：字符串列默认是 `str` 类型，不再是 `object`。判断 `dtype == object` 的旧代码可能失效；字符串列的缺失值统一是 NaN。

### 7. 什么时候不用 pandas

几万个细胞 × 几万个基因的单细胞矩阵大多是稀疏的，存成 pandas 宽表既费内存又慢，应该用 AnnData / scanpy（第 21 周）。pandas 更适合样本信息、基因注释、分析结果这类“元数据和结果表”。

**第 1 步：构造数据并完成分析。** 我们模拟一个 RNA-seq 实验：6 个样本（对照、处理各 3 个），200 个基因，其中 G0001–G0010 在处理组中被“埋下”了 4 倍上调，看分析能不能把它们找出来。

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(42)

# 1) 样本信息表：6 个样本，对照与处理各 3 个，分两个批次
samples = pd.DataFrame({
    "sample": [f"S{i}" for i in range(1, 7)],
    "condition": ["control"] * 3 + ["treated"] * 3,
    "batch": ["b1", "b2", "b1", "b2", "b1", "b2"],
})

# 2) 计数矩阵（宽表）：200 个基因 × 6 个样本；G0001–G0010 在处理组上调 4 倍
n_genes = 200
gene_ids = [f"G{i:04d}" for i in range(1, n_genes + 1)]
base = rng.gamma(shape=2.0, scale=50, size=n_genes)        # 每个基因的基础表达量
fold = np.ones((n_genes, 6))
fold[:10, 3:] = 4.0                                        # 埋下“真实”的上调信号
counts = pd.DataFrame(rng.poisson(base[:, None] * fold), index=gene_ids, columns=samples["sample"])

# 3) 基因注释表：前 5 个基因缺少注释
annot = pd.DataFrame({
    "gene_id": gene_ids[5:],
    "symbol": [f"GENE{i}" for i in range(6, n_genes + 1)],
    "biotype": rng.choice(["protein_coding", "lncRNA"], size=n_genes - 5, p=[0.8, 0.2]),
})
print(counts.shape)
print(counts.iloc[:3, :4])

# 4) 过滤低表达基因：至少 3 个样本的计数 ≥ 10
keep = (counts >= 10).sum(axis=1) >= 3
counts = counts.loc[keep]
print(f"保留 {keep.sum()} / {len(keep)} 个基因")

# 5) CPM 归一化 + log2：每一列除以该样本的总计数（按列名自动对齐）
cpm = counts / counts.sum(axis=0) * 1e6
logcpm = np.log2(cpm + 1)

# 6) 宽表 → 长表，合并样本信息，再按 (基因, 条件) 分组求均值
long = (logcpm.reset_index(names="gene_id")
              .melt(id_vars="gene_id", var_name="sample", value_name="logcpm")
              .merge(samples, on="sample", how="left", validate="many_to_one"))
print(long.head(3))
means = long.groupby(["gene_id", "condition"])["logcpm"].mean().unstack("condition")
means["log2fc"] = means["treated"] - means["control"]

# 7) 合并基因注释（左连接：没有注释的基因也保留），按倍数变化排序
result = (means.reset_index()
               .merge(annot, on="gene_id", how="left", validate="one_to_one")
               .sort_values("log2fc", ascending=False))
top = result.head(10)
print(top[["gene_id", "symbol", "control", "treated", "log2fc"]].round(2).to_string(index=False))
print("前 10 名中埋下的真信号个数：", top["gene_id"].isin(gene_ids[:10]).sum())
result.to_csv("de_results.csv", index=False)
```

## ✅ 自测题

1. `counts / counts.sum(axis=0)` 在 pandas 中是怎么对齐的？它和 NumPy 的广播有什么不同？
2. `df.loc["G0001":"G0003"]` 和 `df.iloc[0:3]` 的切片规则有什么区别？
3. 为什么合并基因注释时要用 `validate="one_to_one"`？如果注释表里同一个基因出现两次，不加检查会发生什么？
4. pandas 3 中，`df[df["log2fc"] > 1]["flag"] = True` 为什么不起作用？正确写法是什么？
5. 练习第 2 步中，埋下的 4 倍上调为什么只算出约 1.8 的 log2FC，而且其他基因的 log2FC 中位数是 −0.2？

<details>
<summary>参考答案</summary>

1. pandas 按标签对齐：`counts.sum(axis=0)` 是一个以样本名为索引的 Series，除法时按样本名与 `counts` 的列逐一配对，每列除以同名样本的总数。NumPy 只按位置和形状广播，不认标签；pandas 中标签对不上时会产生 NaN，而不是报错。
2. `loc` 按标签切片，包含终点，取 G0001、G0002、G0003 三行；`iloc` 按位置切片，和 Python 一样不包含终点，取第 0、1、2 行。
3. 一旦注释表里有重复键，合并后对应的行会被复制，表达结果的行数悄悄增加，后续统计（如上调基因数）就会出错。`validate="one_to_one"` 会在键不唯一时立即报错，让问题在第一时间暴露。
4. 在写时复制模式下，`df[df["log2fc"] > 1]` 得到的是一个新对象，对它赋值不会写回 `df`，所以 `df` 不变。正确写法是 `df.loc[df["log2fc"] > 1, "flag"] = True`，一步完成筛选和赋值。
5. 这是组成偏差（compositional bias）。10 个基因上调 4 倍，让处理组样本的总计数增加了约 17%。CPM 用总计数做分母，于是处理组里所有基因的 CPM 都被压低约 17%：上调基因的倍数被低估（$\log_2(4/1.17) \approx 1.8$），没有变化的基因则显得“下调”了约 0.2（$\log_2(1/1.17) \approx -0.22$）。DESeq2 的中位数比值法、edgeR 的 TMM 等归一化方法假设大多数基因不变，正是为了纠正这种偏差。

</details>
