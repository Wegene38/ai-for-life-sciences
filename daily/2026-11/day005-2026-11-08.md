## 📖 核心概念

### 1. 为什么生信离不开命令行

- **数据量大**：一个 FASTQ 文件动辄几个 GB，Excel 打不开，也没必要整个读进 Python。命令行工具逐行处理数据流，几乎不占内存。
- **核心工具都是命令行程序**：samtools、bwa、STAR、bedtools 等，集群和云服务器基本都运行 Linux。
- **可以组合**：Unix 的思路是“每个小工具只做好一件事”，再用管道 `|` 把它们串起来，就能完成复杂的任务。
- **可以复现**：把命令写进脚本，就是一份精确、可重跑的分析记录。

### 2. 基本概念

- **shell**（如 bash、zsh）是解释和执行命令的程序，终端只是显示它的窗口。macOS 默认用 zsh，日常命令与 bash 基本一致；Windows 用户推荐装 WSL（适用于 Linux 的 Windows 子系统）。
- **路径**：绝对路径从根目录写起（`/home/me/data/a.fa`），相对路径从当前目录写起（`data/a.fa`）。`~` 是家目录，`.` 是当前目录，`..` 是上一级目录。按 Tab 键自动补全，能少打很多错字。路径区分大小写，文件名里不要用空格。
- **命令的结构**：`命令 -选项 参数`，例如 `head -n 8 reads.fastq`。查帮助用 `man head` 或 `head --help`。
- **输入输出**：命令的结果默认打印到屏幕（标准输出），报错信息走另一条通道（标准错误）。`>` 把输出写进文件（覆盖），`>>` 追加到文件末尾，`|` 把前一个命令的输出交给下一个命令。注意：`rm` 删除的文件不会进回收站。

### 3. 生信常见文本格式

| 格式 | 结构 | 命令行里怎么用 |
|---|---|---|
| FASTA | 以 `>` 开头的标题行，后面是序列行（序列可能分成多行） | `grep -c '^>'` 统计序列条数 |
| FASTQ | 每条 read 固定 4 行：`@名字`、序列、`+`、质量字符串 | 总行数 ÷ 4 = reads 数；`awk 'NR % 4 == 2'` 取出所有序列行 |
| GTF / GFF | 制表符分隔的 9 列：染色体、来源、类型、起点、终点、得分、链、相位、属性。坐标从 1 开始，起点和终点都包含在内 | `cut -f3 \| sort \| uniq -c` 统计各类特征 |
| BED | 至少 3 列：染色体、起点、终点。**起点从 0 开始，终点不包含在内** | GTF 转 BED 时起点要减 1 |
| SAM/BAM、VCF | 比对结果、变异记录 | 用 samtools、bcftools 处理（Day 034 会讲） |

FASTQ 的质量字符串里，每个字符对应一个碱基的测序质量：质量值 $Q = -10\log_{10} P_{\text{错误}}$，字符的 ASCII 码等于 $Q + 33$。例如字符 `I` 的 ASCII 码是 73，对应 $Q = 40$，即错误率 $10^{-4}$。

坐标约定是生信里最常见的“差一错误”来源：同一个外显子，在 GTF 里写作 `1000–1200`，在 BED 里要写成 `999–1200`。格式细节可以查 [UCSC 格式说明](https://genome.ucsc.edu/FAQ/FAQformat.html) 和 [Ensembl 的 GFF/GTF 说明](https://www.ensembl.org/info/website/upload/gff.html)。

### 4. 文本处理的基本套路

- `grep` 找行，`cut` 或 `awk` 取列，`sort | uniq -c` 计数，`wc -l` 数行数。
- `awk` 的基本形式是 `awk '条件 {动作}'`：`NR` 是当前行号，`$3` 是第 3 列，`-F'\t'` 指定用制表符分列。
- 压缩文件不用先解压到硬盘：`gzip -cd file.fastq.gz | 后续命令` 边解压边处理（Linux 上也可以用 `zcat`，但 macOS 自带的 `zcat` 不认 `.gz`）。

### 5. 循环与脚本

对多个样本做同样的事，用 `for` 循环；`${f%.fastq.gz}` 可以去掉文件名后缀，得到样本名。把命令写进 `.sh` 脚本，并在开头加上 `set -euo pipefail`：任何一步出错就立即停止、使用未定义的变量会报错、管道中任何一环失败都算失败，避免带着错误结果继续往下跑。

### 6. 命令行和 Python 怎么分工

快速查看、计数、筛选、批量跑工具，用命令行；复杂逻辑、统计建模、画图，用 Python。两者经常配合：先用命令行整理出小表格，再交给 pandas 分析。

## 🛠️ 动手练习

**运行环境**：本地终端（Windows 用 WSL），或者 Colab。在 Colab 里，单元格第一行写 `%%bash`，整个单元格就会按 bash 执行。

**第 1 步：生成练习数据。** 下面的 Python 代码会生成一份玩具 FASTA、三个样本的 FASTQ.gz 和一份 GTF 注释（坐标和基因名都是虚构的）：

```python
import gzip
import random

random.seed(0)
BASES = "ACGT"

def random_seq(length):
    return "".join(random.choice(BASES) for _ in range(length))

# 1) toy.fa：5 条序列，每行 60 个碱基（FASTA 的常见写法）
with open("toy.fa", "w") as f:
    for i in range(1, 6):
        seq = random_seq(random.randint(80, 120))
        f.write(f">seq{i} toy sequence {i}\n")
        for j in range(0, len(seq), 60):
            f.write(seq[j:j + 60] + "\n")

# 2) 三个样本的 FASTQ.gz：每条 read 占 4 行（@名字、序列、+、质量）
for sample, n_reads in [("sampleA", 1000), ("sampleB", 1500), ("sampleC", 800)]:
    with gzip.open(f"{sample}.fastq.gz", "wt") as f:
        for i in range(n_reads):
            length = random.randint(90, 100)
            quality = "".join(chr(33 + random.randint(20, 40)) for _ in range(length))
            f.write(f"@{sample}_read{i}\n{random_seq(length)}\n+\n{quality}\n")

# 3) toy.gtf：3 个基因的注释（制表符分隔的 9 列，坐标从 1 开始、包含两端）
genes = [
    ("chr1", "+", "G1", "geneA", [(1000, 1200), (2500, 2700), (4800, 5000)]),
    ("chr2", "-", "G2", "geneB", [(300, 600), (2000, 2300)]),
    ("chr3", "+", "G3", "geneC", [(700, 900), (1300, 1500)]),
]
with open("toy.gtf", "w") as f:
    for chrom, strand, gid, name, exons in genes:
        start, end = exons[0][0], exons[-1][1]
        attr = f'gene_id "{gid}"; gene_name "{name}";'
        f.write(f"{chrom}\ttoy\tgene\t{start}\t{end}\t.\t{strand}\t.\t{attr}\n")
        f.write(f'{chrom}\ttoy\ttranscript\t{start}\t{end}\t.\t{strand}\t.\t{attr} transcript_id "{gid}.1";\n')
        for s, e in exons:
            f.write(f'{chrom}\ttoy\texon\t{s}\t{e}\t.\t{strand}\t.\t{attr} transcript_id "{gid}.1";\n')

print("已生成：toy.fa、sampleA/B/C.fastq.gz、toy.gtf")
```

**第 2 步：用命令行回答问题。** 先自己想想怎么写，再对照下面的答案。因为随机种子固定，你的输出应该和注释里的完全一样：

```bash

                                                 # GC 含量 → 0.458

echo $(( $(gzip -cd sampleA.fastq.gz | wc -l) / 4 ))
                                                 # sampleA 有多少 reads？→ 1000
gzip -cd sampleA.fastq.gz | awk 'NR % 4 == 2 {n++; total += length($0)} END {printf "%.1f\n", total / n}'
                                                 # 平均读长 → 95.2

                                                 # 含 EcoRI 酶切位点 GAATTC 的 reads 数 → 19
cut -f3 toy.gtf | sort | uniq -c                 # 各类特征有几条？→ 7 exon、3 gene、3 transcript
awk -F'\t' '$3 == "gene"' toy.gtf | grep -o 'gene_name "[^"]*"' | cut -d'"' -f2
                                                 # 注释里有哪些基因？→ geneA geneB geneC
```

**第 3 步：写一个统计 reads 数的脚本。**

```bash
cat > count_reads.sh <<'EOF'
#!/usr/bin/env bash
# 统计当前目录下每个 FASTQ.gz 文件的 reads 数，输出制表符分隔的表格
set -euo pipefail
printf "sample\treads\n"
for f in *.fastq.gz; do
    n=$(( $(gzip -cd "$f" | wc -l) / 4 ))
    printf "%s\t%s\n" "${f%.fastq.gz}" "$n"
done
EOF
bash count_reads.sh > read_counts.tsv
cat read_counts.tsv
```

期望输出：

```
sample	reads
sampleA	1000
sampleB	1500
sampleC	800
```

生成的 `read_counts.tsv` 可以直接用 `pandas.read_csv("read_counts.tsv", sep="\t")` 读进 Python 继续分析。

## ✅ 自测题

1. 为什么 FASTQ 文件的“总行数 ÷ 4”就是 reads 数？什么情况下这个算法会出错？
2. `>`、`>>` 和 `|` 分别做什么？
3. GTF 里有一个外显子写作 `chr1 … 1000 1200`，换成 BED 格式应该怎么写？为什么？
4. FASTQ 质量字符 `I` 对应的 Phred 质量值和测序错误率是多少？
5. 脚本开头的 `set -euo pipefail` 有什么作用？

<details>
<summary>参考答案</summary>

1. 标准 FASTQ 中每条 read 固定占 4 行（名字、序列、`+`、质量）。如果文件是早期那种序列和质量分成多行书写的 FASTQ，或者文件末尾有多余的空行、文件被截断，这个算法就会出错。正式分析时可以用 `seqkit stats` 这类专门工具核对。
2. `>` 把命令输出写入文件，文件已存在时会被覆盖；`>>` 把输出追加到文件末尾；`|`（管道）把前一个命令的输出直接作为后一个命令的输入，中间不产生文件。
3. 写成 `chr1	999	1200`。GTF 的坐标从 1 开始，起点和终点都包含在内；BED 的起点从 0 开始，终点不包含在内。同一段区间，BED 的起点要减 1，终点不变。
4. `I` 的 ASCII 码是 73，减去 33 得到 $Q = 40$，错误率 $P = 10^{-Q/10} = 10^{-4}$，也就是万分之一。
5. `-e`：任何命令出错就立即退出；`-u`：使用未定义的变量时报错（防止拼错变量名导致 `rm -rf $DIR/` 这类危险操作）；`-o pipefail`：管道中任何一个命令失败，整条管道都算失败。合起来能避免脚本带着错误继续运行、产生看起来正常但实际错误的结果。

</details>
