## 📖 核心概念

### 1. 为什么环境管理是科研基本功

“在我电脑上能跑”是计算研究里最常见的失败之一。生物 AI 的依赖尤其复杂：scanpy 对 numpy、anndata 的版本有要求；PyTorch 要和显卡驱动、CUDA 版本匹配；RDKit、samtools 这类带 C/C++ 底层的工具用 pip 很难装好。一条基本原则：**一个项目一个环境**，不要把所有包都装进系统 Python 或 conda 的 base 环境。

### 2. 三类运行环境

| 环境 | 优点 | 限制 | 适合 |
|---|---|---|---|
| Google Colab | 零配置，免费 GPU（通常是 16 GB 显存的 T4） | 单次会话最长约 12 小时，闲置约 90 分钟断开；配额是动态的、不保证；断开后虚拟机里的文件会清空 | 练习、跑通官方示例 |
| Kaggle Notebooks | 每周约 30 小时免费 GPU，单次最长 12 小时；一键挂载海量公开数据集 | 要先完成手机号验证才能用 GPU 和联网；配额会随需求浮动 | 比赛、中等规模训练 |
| 本地电脑 | 完全可控、数据不出本机、可长期运行 | 没有 NVIDIA 显卡时训练深度模型很慢；环境要自己维护 | 数据分析、写代码、长期项目 |
| 国内平台（魔搭、百度 AI Studio） | 国内访问稳定 | 免费额度和预装环境以官网为准 | 访问不了 Colab / Kaggle 时 |

> 上表的时长和配额来自各平台说明及多方报告，平台会随时调整，以官网为准。

推荐的工作流：**本地写代码、用小数据调试 → 云端 GPU 跑训练 → 代码和结果回到 Git**。云端 Notebook 的文件随时可能消失，重要的东西要及时存到 Google Drive、Kaggle Dataset 或 GitHub。

### 3. 包管理：pip、conda、mamba

- **pip**：从 PyPI 安装 Python 包，轻量，但不管理 Python 本身和非 Python 的依赖。
- **conda**：既管理“环境”（独立的 Python 版本加一套包），也能安装 C 库、CUDA 工具包和命令行生信工具。生信工具（samtools、bwa 等）在 [Bioconda](https://bioconda.github.io/) 频道，只支持 Linux 和 macOS。
- **mamba**：与 conda 用法相同、求解依赖更快的实现。新版 conda 默认也已经用上了 mamba 的求解器（libmamba）。
- **Miniforge**：推荐的安装包，自带 conda 和 mamba，默认只用社区维护的 conda-forge 频道。Anaconda 官方的 `defaults` 频道受其服务条款约束，机构用户可能需要付费授权，很多大学因此已经建议改用 Miniforge。

经验法则：先用 conda 安装能找到的包，conda 里没有的再用 pip，并且只在激活的项目环境里用 pip。

### 4. 环境文件：让环境可复现

`environment.yml` 写明环境名、频道和依赖，别人一条命令就能重建同样的环境。导出时有两种方式：

- `conda env export --from-history`：只记录你**明确要求安装**的包，跨操作系统更容易重建，适合分享。
- `conda env export`：记录所有包的精确版本和构建号，复现性最强，但通常只能在相同的操作系统上重建，适合归档论文结果。

### 5. Jupyter 的正确用法

Notebook 把代码、输出和文字放在一起，非常适合探索分析。但它有一个隐患：单元格可以乱序执行，内存里会留下“隐藏状态”。比如删掉了定义变量的单元格，变量却还在内存里，于是代码看起来能跑，别人打开却会报错。**分享或提交前，先“重启并全部运行”**（Restart & Run All）。

常用技巧：`?` 查看帮助；`%timeit` 计时；`%pip install` 把包装进当前内核；`!nvidia-smi` 运行 shell 命令。需要反复调用的代码，最后应该整理成 `.py` 模块（Day 013 会讲）。

### 6. GPU 什么时候有用

GPU 擅长大规模并行的矩阵运算，所以深度学习的训练和推理离不开它。经典机器学习（scikit-learn）和大多数生信流程（比对、计数、差异分析）基本用不上 GPU。显存决定能装下多大的模型和批量：T4 的 16 GB 显存足够推理 6.5 亿参数的 ESM-2，或者训练本课程里的小模型，但装不下大型基础模型的训练。

### 7. 国内访问提示

- pip 换源：`pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`（清华 TUNA 镜像）。
- conda 换源：按 [TUNA 的 Anaconda 镜像帮助](https://mirrors.tuna.tsinghua.edu.cn/help/anaconda/) 修改 `~/.condarc`。
- Hugging Face 模型：设置环境变量 `HF_ENDPOINT=https://hf-mirror.com`（社区镜像）。
- 访问不了 Colab / Kaggle 时，可以改用魔搭或 AI Studio，见 [12 工具与算力](../../resources/12-tools-compute.md#国内学习者提示)。

## 🛠️ 动手练习

**第 1 步：在云端打开 GPU。**

- Colab：菜单“代码执行程序 → 更改运行时类型”，选择 T4 GPU。
- Kaggle：Notebook 右侧 Settings → Accelerator，选择 GPU（需要先完成手机号验证）。

然后在单元格里运行 `!nvidia-smi`，能看到显卡型号和显存，说明 GPU 已分配。

**第 2 步：运行环境报告与 CPU / GPU 对比。** Colab 已预装 PyTorch，可以直接运行：

```python
import os, sys, time, platform
import importlib.metadata as md
import numpy as np

# 1) 环境报告：Python 版本、系统、CPU、关键包版本
print("Python:", sys.version.split()[0], "|", platform.platform())
print("CPU 核心数:", os.cpu_count())
for pkg in ["numpy", "pandas", "scikit-learn", "torch", "biopython"]:
    try:
        print(f"{pkg:>13}: {md.version(pkg)}")
    except md.PackageNotFoundError:
        print(f"{pkg:>13}: 未安装")

# 2) CPU：用 NumPy 做一次 4096 × 4096 的矩阵乘法
n = 4096
a = np.random.rand(n, n).astype(np.float32)
t0 = time.perf_counter()
a @ a
cpu_s = time.perf_counter() - t0
print(f"CPU（NumPy）矩阵乘法：{cpu_s:.3f} 秒")

# 3) GPU：有 PyTorch 和 CUDA 时，用 GPU 做同样的计算
try:
    import torch
    if torch.cuda.is_available():
        print("GPU:", torch.cuda.get_device_name(0))
        x = torch.rand(n, n, device="cuda")
        x @ x
        torch.cuda.synchronize()          # 预热：第一次调用包含初始化开销，不计时
        t0 = time.perf_counter()
        x @ x
        torch.cuda.synchronize()          # GPU 是异步执行的，要等它算完再停表
        gpu_s = time.perf_counter() - t0
        print(f"GPU（PyTorch）矩阵乘法：{gpu_s:.4f} 秒，约快 {cpu_s / gpu_s:.0f} 倍")
    else:
        print("没有检测到 GPU：Colab 里选“代码执行程序 → 更改运行时类型 → T4 GPU”")
except ImportError:
    print("没有安装 PyTorch，跳过 GPU 测试")
```

期望结果：打印出版本信息和两次计时。具体数字取决于分到的机器，一般来说 GPU 会快几十倍。如果显示“没有检测到 GPU”，回到第 1 步检查运行时类型。

**第 3 步：在本地建一个可复现的环境。** 按 Miniforge README 安装后，把下面的内容存为 `environment.yml`：

```yaml
name: ai4ls
channels:
  - conda-forge
  - bioconda
dependencies:
  - python=3.12
  - numpy
  - pandas
  - matplotlib
  - scikit-learn
  - jupyterlab
  - biopython
  - pip
  - pip:
      - py3Dmol
```

然后在终端里依次运行（把 `conda` 换成 `mamba` 用法完全一样）：

```bash
conda env create -f environment.yml                # 按文件创建环境
conda activate ai4ls                               # 激活环境
python -c "import Bio, sklearn; print('环境可用')"   # 检查关键包
jupyter lab                                        # 打开 JupyterLab
conda env export --from-history > my-env.yml       # 导出“明确安装过的包”
```

**进阶：** 把第 2 步改成循环，对 `n = 256, 512, 1024, 2048, 4096, 8192` 分别计时，画出“GPU 加速倍数 vs 矩阵大小”的折线图。你会发现矩阵很小时 GPU 几乎不快，甚至更慢。想一想为什么（提示：数据传输和启动计算本身也要时间）。

## ✅ 自测题

1. Colab 和 Kaggle 的免费 GPU 各有哪些主要限制？如果一次训练要连续跑 20 小时，你会怎么安排？
2. pip 和 conda 的区别是什么？为什么 samtools 这类生信工具通常用 conda 安装？
3. 为什么分享 Notebook 之前要“重启并全部运行”？
4. `conda env export --from-history` 和 `conda env export` 导出的文件有什么不同？各适合什么场景？
5. 为什么用 GPU 计算 64 × 64 的小矩阵乘法，可能比 CPU 还慢？

<details>
<summary>参考答案</summary>

1. Colab：单次会话最长约 12 小时，闲置会断开，配额动态变化、不保证 GPU，断开后文件清空。Kaggle：每周约 30 小时 GPU 配额，单次最长 12 小时，需手机号验证。20 小时的训练要拆开跑：定期保存检查点（checkpoint）到云盘或 Kaggle 输出，断开后从检查点恢复；也可以先缩小数据或模型，确认值得跑这么久。
2. pip 只从 PyPI 装 Python 包，不管理 Python 版本和系统级依赖；conda 管理整个环境，还能装编译好的 C/C++ 程序和库。samtools 这类工具主要由 C 写成，依赖 htslib 等系统库，Bioconda 提供了编译好的版本，一条命令就能装好。
3. Notebook 可以乱序执行，内存里可能残留已删除单元格定义的变量（隐藏状态）。只有从头按顺序跑通，才能证明别人打开后也能得到相同结果。
4. `--from-history` 只记录你明确安装过的包、不锁定构建号，跨平台重建更容易，适合分享给他人；完整导出记录所有依赖的精确版本和构建号，复现性最强，但通常只能在相同操作系统上重建，适合归档论文结果。
5. GPU 计算前要把数据从内存搬到显存、启动计算核心（kernel），这些固定开销在小矩阵上会超过计算本身节省的时间。只有计算量足够大时，GPU 的并行优势才会体现出来。

</details>
